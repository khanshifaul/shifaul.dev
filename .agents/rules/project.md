## Architecture

**frontend.shifaul.dev** — Shifaul's public portfolio, blog, resume and client
area: a Next.js 16 App Router frontend that reads all of its data from a
separate backend API. No `src/` directory; the app lives at the repo root.

- Application shape: **one** Next.js app (`bun dev` / `bun run build`), no
  service of its own. The backend is external, reached over REST at
  `NEXT_PUBLIC_API_URL` (`.env.example`: `http://localhost:4000/api`). Four
  route handlers under `app/api/` exist only as thin pass-throughs
  (`projects`, `sitemap`, `sitemap/[sitemap]`, `sitemap/paginated`) to the same
  client modules the browser uses.
- Persistence layer: **none in this repo** — no database, ORM, or migrations.
  All state lives in the backend. `lib/actions/*` are typed `fetch` clients:
  `authAPi`, `blogApi`, `projectsApi`, `contactApi`, `newsletterApi`,
  `analyticsApi`, `adminUserApi`.
- Client side: React `19.2.4` Server Components; client state in Redux Toolkit
  (`lib/store/`), theme via `next-themes`, styling with Tailwind 4
  (`app/globals.css` + `postcss.config.mjs`; there is no `tailwind.config.*`),
  blog content via `next-mdx-remote` + `remark-gfm`/`remark-math`/KaTeX,
  charts via `recharts`, maps via `leaflet`/`react-leaflet`.
- Access control: root `proxy.ts` is the Next 16 request proxy (the renamed
  `middleware.ts`). It adds `x-requires-auth` / `x-required-role` headers for
  `/admin` and `/dashboard`, `/profile`, `/settings`; it does **not** enforce
  auth — the JWT check is client-side (`authHelpers.checkAuth`, localStorage).
  Treat it as routing, not a security boundary.
- Test command: **none — this project has no test suite** (no runner in
  `package.json`, no `*.test.*` / `*.spec.*`, no `.github/workflows`). The gate
  is typecheck: `bunx tsc --noEmit` — green on master, measured 2026-10-21.
  `bun run build` is the fuller check. `bun run lint` is red on master; see
  **Conventions**.

Before writing a plan, spec, or import: **check the tree first.** Never write
against a service that is not on disk. If this file disagrees with the tree,
the tree is right and this file is a bug — fix it here.

## Conventions this project has that the office does not

- **Bun, not npm.** `bun install`, `bun run lint`, `bunx tsc --noEmit`. A
  `package-lock.json` would be a new lockfile and a bug.
- **`bun run lint` is currently red on master** — 250 errors and 48 warnings
  across `app/`, `components/`, `hooks/`, `lib/` and `proxy.ts`, measured
  2026-10-21. A brief must not gate on lint until that is cleared; do not
  clear it inside an unrelated diff.
- **Typecheck is the gate.** There is no test suite to extend; a change that
  needs proof gets a throwaway script, not a new test framework.
- **No backend verification.** Anything whose correctness depends on the API's
  response shape is `[INFERENCE]` here until exercised against a running
  backend; say so instead of claiming it works.
- **Deploy is Vercel, and production is `gate: human`.** The production env
  (`NEXT_PUBLIC_API_URL`) is not in the tree; only `.env.example` is.
- `next.config.ts` pins `outputFileTracingRoot` to this directory on purpose —
  a sibling lockfile above the repo confused Turbopack once. Do not remove it
  without reproducing that failure.
- Next 16 pages are `.tsx` **or** `.md`/`.mdx` (`pageExtensions`); a new
  extension needs a config change, not just a new file.
